# DAT 汉化技术说明

本文记录当前 `v0.1.0-preview.1` 的可复现技术基线、Clickteam Fusion DAT 写回约束和验证结果。这里不提供完整游戏资源，也不包含可独立重建游戏内容的原始 DAT。

## 输入与输出

| 用途 | 大小 | SHA-256 |
| --- | ---: | --- |
| Steam 英文原版 DAT | 613,928,694 | `3D393F2160A5868B51AB07F5EEE246EBF297151F9C841C3AF3F300B2B0818FDB` |
| 中文 v8 DAT | 618,844,371 | `7FB74B7E333B4B274038678D68BA23138A89CB7CC56D5938DAB698470EFB48EA` |
| Zstandard 差分补丁 | 98,132,044 | `FE7E5EAAFE02A64B7F3148CB0C83ECD4462C59CB3503769CDB09E9342761CAFF` |

Release 中的补丁以英文原版为参考字典，使用 Zstandard 1.5.7 的 `--patch-from` 模式生成。解码时必须使用 `--long=30`，否则默认窗口上限不足，会出现 `Frame requires too much memory for decoding`。发布前已由 Release 内同一份 `zstd.exe` 反向重建目标 DAT，输出大小和 SHA-256 均完全一致。

## 文本与字体

结构化写入范围：

- 1,093 条事件映射，共命中 372,140 个字符串槽位。
- 205 个对象段落和 2 个对象可变字符串。
- 4 个内嵌 TrueType 字体和 6 个运行时字体句柄。
- 译文共使用 1,437 个不同字符，均被替换字体覆盖。

翻译以英文与韩文文本交叉对照，使用 `gpt-5.6-luna`、`max` 推理强度生成第一轮译稿。随后检查键列、行数、UTF-16 槽位长度、数字、控制符、占位符、韩文残留和字体覆盖。构建器遇到超长、冲突或未解析行会终止，不会静默截断。

## Clickteam 写回约束

### zlib 字节流兼容

事件块使用原生 zlib 1.2.11、压缩级别 6；对象属性条目使用压缩级别 9。早期采用 .NET `ZLibStream` 生成的流能被标准库解压，却会让 Fusion 运行时误报 `Cannot load mmfs2.dll`。因此“标准 zlib 可解压”不等于“Clickteam 运行时兼容”。

### ObjectPropOffsets

对象文本和字体改变 `0x2256 ObjectProperties` 的压缩后尺寸。每次写回后都必须重新计算全部 7,232 个对象偏移并重建 `0x2257 ObjectPropOffsets`。保留旧偏移时，进程可能仍然响应，却不会创建游戏窗口。

### 保护校验

所有受保护块写回后必须重算 `0x2242`。校验范围从第一个 `0x222F` 块头开始，到 `0x2242` 块头之前结束。主体按小端 `uint32` 执行：

```text
checksum = ROL32(checksum, 1) + value
```

末尾不足四字节时逐字节继续同一旋转加法。存储前还需按该块规则处理低字节。未更新校验也会表现为 `mmfs2.dll` 加载失败。

### 图片资源

菜单、标签和部分提示不是文本对象，而是烘焙图片。当前英文与韩文包均包含 17,143 个可解码图片句柄，其中 480 个相同句柄的内容不同。v8 已替换 16 张主菜单和暂停菜单图片。

修改 `0x6666 ImageBank` 后必须同步重建 `0x5555 ImageOffsets`，并重新计算保护校验。图片写回器先以原图片做无损回归，重建 DAT 与输入哈希完全相同；v8 的 16 张替换图回读后总像素差为零。

## 验证结果

发布候选依次通过：

- 译表结构、长度、占位符、控制符和字体覆盖检查。
- 独立 Nebula 全量解析 454/454 个帧、2,354,565 条事件行、7,232 个对象属性记录和 30,002 条对象文本。
- 全量解码 17,143 张图片，16 张替换图逐像素一致。
- 块级比较确认图片阶段只改变 `0x6666 ImageBank` 和 `0x5555 ImageOffsets`。
- 在真实 Steam 安装目录经 AppID 1674780 启动，窗口存在、句柄有效、进程响应正常。
- 进程加载 `Steamworks.mfx`、`steam_api.dll`、`steamclient.dll` 和 `gameoverlayrenderer.dll`，覆盖层提示正常显示。

## 已确认的故障模式

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot load mmfs2.dll` | .NET zlib 输出不被 Fusion 接受 | 使用原生 zlib 1.2.11 和对应压缩级别 |
| `Cannot load mmfs2.dll` | 受保护块修改后未更新 `0x2242` | 重算保护校验 |
| 进程正常但无窗口 | `0x2256` 改变后仍使用旧 `0x2257` | 重建全部对象属性偏移 |
| 原版在隔离目录也报错 | 测试目录缺少完整运行环境 | 必须在真实 Steam 目录测试 |
| 正文中文但菜单韩文 | 文字被烘焙到图片 | 修改图片银行和偏移表 |
| 差分解码内存错误 | 未启用足够大的长距离窗口 | 解码加 `--long=30` |

## 成就兼容边界

补丁没有修改 EXE、Steamworks 扩展、Steam API、AppID 或成就机器标识。运行时模块和覆盖层均正常加载，因此未发现任何会禁用成就的技术变化。为避免永久改变账号，没有调用强制解锁接口；自然触发尚未获得的成就是最后一项用户态验收。
